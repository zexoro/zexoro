## 1. Components

| Component | Where | Notes |
| --- | --- | --- |
| NSIS toolset | `zexoro/nsis-toolset` | NSIS 3.13 built from source. `makensis` built natively per host (linux-x64, linux-arm64, osx-x64, osx-arm64, win-x64); stubs and plugins cross-compiled once with mingw-w64 on Linux. Published as GitHub releases: `nsis-3.13-zexoro.<n>-<rid>.tar.gz` plus `SHA256SUMS`. |
| Platform model | `Zexoro.Core` | `TargetPlatform` = operating system + architecture, with RID-style names (`win-x64`). Open set: Android and iOS fit without changes. |
| TOML parser | `Zexoro.Toml` | TOML 1.1.0 into a document model that keeps line and column for every key and value. Conformance: the `toml-test` 2.2.0 valid and invalid cases, vendored under `tests/`. |
| Configuration | `Zexoro.Core` | Typed model of `zexoro.toml` with validation. Unknown keys are errors, so typos never pass silently. Every error points at a line and column. |
| Authenticode | `Zexoro.Signing` | Signs PE files (exe, dll) from a PFX with RSA or ECDSA keys, with an RFC 3161 timestamp. CMS `SignedData` is built with `System.Formats.Asn1`: `System.Security.Cryptography.Pkcs` is not part of the shared framework, and the runtime-dependency rule keeps it out. |
| NSIS back end | `Zexoro.Formats.Nsis` | Generates an `.nsi` script from the configuration, runs the bundled `makensis`, signs the results. |
| CLI | `Zexoro.Cli` | `init`, `pack`, `doctor`. |

## 2. Shipping the toolset

The CLI stays a single file. At build time, the release workflow downloads the pinned toolset for the target RID (version and SHA-256 recorded in `eng/toolsets.json`) and embeds it as a resource. At run time, zexoro extracts it once into a versioned cache directory (`%LOCALAPPDATA%\zexoro`, `~/Library/Caches/zexoro`, `$XDG_CACHE_HOME/zexoro`) and verifies the hash before each use. Nothing is downloaded at run time.

## 3. Installer behavior

- **Layout** (update contract): `<root>\app\…`, `<root>\zexoro-install.json`, `<root>\uninstall.exe`.
- **Roots:** per-user `%LOCALAPPDATA%\Programs\<name>` (no elevation); per-machine `%ProgramFiles%\<name>` (64-bit view for x64 and arm64 apps, elevation requested by the installer).
- **Identity:** uninstall key `HKCU|HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\<app.id>` with name, version, publisher, icon, install location, estimated size, `UninstallString`, `QuietUninstallString`, `NoModify`, `NoRepair`.
- **Upgrade:** if the key exists, the installer refuses to run while the application is running, removes `<root>\app` and installs the new files, then updates the key. Same version reinstalls; a lower version is refused (exit code 3 in silent mode).
- **Uninstall:** removes the root, shortcuts and key. User data is kept; `[windows.uninstall] remove = [...]` lists extra paths to delete.
- **Shortcuts:** Start menu by default; desktop optional. Both point into `<root>\app\`.
- **UI:** Modern UI 2, English only: optional license page, progress, finish page with a "launch" option. Silent mode `/S` and `/D=` work for every scope.
- **Installer metadata:** version resource from the SemVer core (`1.2.3` → `1.2.3.0`), the application icon, Unicode, LZMA solid compression. The stub is x86-unicode, which runs on x64 and arm64 Windows.

## 4. Signing order

1. Application PE files that are not already signed (main executable by default; `sign = "all"` covers every PE file).
2. The uninstaller, through NSIS `!uninstfinalize`, which calls the running zexoro executable's internal `sign-file` command.
3. The installer, through `!finalize`.

Without a certificate, signing is skipped and `pack` prints a notice.

## 5. Tests

- **Unit**, on all three CI platforms: TOML conformance, configuration validation, script generation (snapshot), PE parsing and Authenticode hash, CMS structure, platform names.
- **Signature verification:** `osslsigncode verify` on Linux CI as an independent check (test-only tool).
- **End-to-end**, GitHub Actions:
  1. Pack two versions of a fixture app (framework-dependent `win-x64` publish, which cross-compiles from any OS) on Ubuntu, macOS and Windows, for both scopes, signed with a throwaway self-signed certificate. Version 1 contains a file that version 2 removes.
  2. On a Windows runner, for each scope: silent install v1 → check files, key, shortcuts, signature (certificate temporarily trusted) and that the app runs → install v2 over it → check the stale file is gone, there is one key with the new version → try installing v1 again and expect refusal → uninstall → check nothing is left except user data.
  3. The scripts live in `tests/e2e/windows/` (plain PowerShell) so they can also run over SSH on a real Windows machine.

## 6. Order of work

Each step is a branch merged into `dev` after CI passes.

1. `nsis-toolset`: build pipeline and first release.
2. Platform model and TOML parser.
3. Configuration model, `init`, `doctor`.
4. NSIS back end, toolset embedding, unsigned `pack`.
5. End-to-end Windows tests.
6. Authenticode signing, including the end-to-end signature checks.
7. Release workflow for the CLI (the same five RIDs as the toolset), README usage, example workflow for users. Then the `dev → main` pull request for review.
